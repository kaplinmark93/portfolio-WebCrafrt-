# Design Document: Блок «ПРОЦЕС РОЗРОБКИ» з морфінгом часток

## 1. Intent & Context
Користувач хоче повністю прибрати попередній статичний блок «СТАНДАРТИ РЕАЛІЗАЦІЇ КОЖНОГО ПРОЄКТУ «ПІД КЛЮЧ»» (`#wc-standards-timeline`) і замінити його на видовищний, технологічний блок **«ПРОЦЕС РОЗРОБКИ»**.

Візуальний референс: концепт із Pinterest / TikTok (`https://ru.pinterest.com/pin/21673641953511891/`, автор mxnncreates).
Ключова ідея: футуристичний темний простір, де жива хмара сяючих часток матеріалізується й морфиться у відповідні тривимірні / векторні символи для кожного етапу створення проєкту.

---

## 2. Goals, Non-Goals & Anti-Goals

### Goals
- **Чисто скрол-орієнтована взаємодія (Scroll-driven):** Користувач не зобов'язаний нічого клікати; плавне обертання коліщатка миші або свайп на телефоні керує прогресом через 6 етапів.
- **Повноекранний Pinned Stage (Варіант B):** Під час проходження блоку контейнер фіксується у в'юпорті (sticky / pinned scrollytelling висотою ~400–600vh загального скролу), створюючи ефект інтерактивного шоуруму.
- **Cinematic Centerpiece (Варіант 1):** У центрі екрана розташована потужна сяюча хмара часток (Canvas 2D/WebGL), яка розчиняється й збирається у форму активного етапу. Знизу розташована витончена плаваюча скляна плашка (Glassmorphism HUD) із номером, назвою етапу, лаконічним текстом та смужкою прогресу (01 → 06).
- **6 узгоджених етапів розробки з маркетинговою іскрою:**
  1. `01. Суть & Залізний кошторис` — символ: Стратегічне креслення / Радар.
  2. `02. Тексти, що продають` — символ: Каркас контенту / Модульна сітка.
  3. `03. Візуальний вау-ефект & 3D` — символ: Кристалічна призма / Алмаз.
  4. `04. Швидкість світла` — символ: Термінал і дужки коду `< />`.
  5. `05. Повний автопілот` — символ: Нейромережа зв'язків / Вузли API та CRM.
  6. `06. Запуск & Свобода` — символ: Ракета на орбіті / Сфера запуску.
- **Висока продуктивність (60 FPS):** Легка фізика часток (векторне притягання до опорних точок форми) без перевантаження процесора.

### Non-Goals
- Жодних обов'язкових модальних вікон чи сторонніх важких бібліотек (Three.js 500KB+ не потрібен, коли чистий HTML5 Canvas 2D / WebGL дає миттєвий запуск і 60 FPS).
- Ніяких статичних нудних списків без руху.

### Anti-Goals
- "Scroll-trap" або неможливість вийти: блок повинен мати чітку висоту доріжки скролу, після якої сторінка природно продовжує рух до калькулятора без застрягання.
- Зниження швидкості завантаження сайту чи збої в наявних тестах `tests/`.

## 3. UI/UX Hierarchy & Visual Architecture

### Layout Structure
- **Контейнер скрол-треку (`.wc-process-scroll-container`):** Висота `350vh` або `400vh`. Забезпечує плавний запас скролу для 6 кроків.
- **Липкий фрейм (`.wc-process-sticky-frame`):** `position: sticky; top: 0; width: 100%; height: 100vh; overflow: hidden; background: #08090f;`.
- **Фоновий Canvas часток (`#wc-process-particle-canvas`):** Займає весь фрейм. Відображає:
  1. Фоновий космічний пил (ambient floating particles).
  2. Активну групу часток (~400–600 часток), які за допомогою пружної фізики (spring physics / easing) летять до цільових координат обраної фігури.
- **Верхній мінімалістичний бейдж:** `// ПРОЦЕС РОЗРОБКИ // SYSTEM WORKFLOW` та індикатор активного кроку `[ 03 / 06 ]`.
- **Нижня скляна картка (`.wc-process-glass-hud`):**
  - Неоновий тег етапу (`ЕТАП 01`).
  - Заголовок та слоган.
  - Опис (2 рядки).
  - Смужка прогресу з неоновим градієнтом (`#7c3aed` → `#c084fc`).
- **Світловий бекдроп:** Радіальний блюр-градієнт під частинками для неонового світіння в стилі `terminal.css`.

## 4. Technical Implementation Details (Left to Builder)
1. **Генерація точок фігур (Shape Coordinate Generators):**
   - 6 параметричних функцій розрахунку точок `(x, y)` або `(x, y, z)` для кожного етапу.
2. **Інтерполяція скролу:**
   - Розрахунок `progress = (scrollY - top) / (height - viewportHeight)`.
   - Визначення поточного індексу етапу `Math.min(5, Math.floor(progress * 6))`.
   - Плавний перехід точок за допомогою `targetX/targetY` та `vx/vy` або lerp з затуханням (damping).
3. **Заміна у розмітці:**
   - Видалення старого `#wc-standards-timeline` у `scripts/terminal.js`.
   - Монтування нової секції `id="wc-process-timeline"` або `id="wc-process-development"`.
   - Оновлення тестів у `tests/reveal-features-test.js` та `tests/integration-test.js` для валідації нового блоку.
